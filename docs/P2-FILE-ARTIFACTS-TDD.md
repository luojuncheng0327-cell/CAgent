## 用户流程与实现范围

用户让助手写入、精确编辑、复制文件或保存附件后，右侧“对话文件”自动展示工具文件及原上传附件。每次成功输出使用对应工具结果消息的稳定编号，保留会话、消息、调用、原路径、字节数与 SHA-256。同名文件不合并，后续同路径修改会使旧版本显示“文件已变化”。

用户可打开文件、下载仍匹配原版本的字节、定位来源消息，或确认移除记录。打开跨根文字文件先切换到它当前所属的已授权根，再用相对路径打开编辑器；干净标签可刷新，已编辑草稿继续保留，源文件仍手动保存。移除记录和删除会话都不删除磁盘文件。

## 失败与修正

- 第一次桌面夹具默认选中了后创建的空会话；改为按稳定会话标题选择，再保留有效的缺入口 RED。记录 `p2-artifacts-desktop-red-20261005.log`，不当作产品缺陷证据。
- 标题出现并不代表异步列表加载完成：保留 20 项断言，增加列表就绪等待。
- 绝对路径图片的读屏名称原为整条路径；改为文件名，完整路径仍在提示中。
- Playwright 的 `download` 事件等待超时。改为监听 Electron 原生 `will-download` / `done`，指定临时保存目录，断言 `completed` 并核对实际文件字节；没有改成模拟下载。
- 先前用测试 API 撤销授权，使渲染器会话版本落后；改为真实目录授权入口。随后发现跨根文字标签导致草稿越界，定位结果增加授权根与相对路径，打开前切根。干净标签刷新当前内容，编辑草稿保留。
- 失败清理只退出该脚本启动的隔离测试应用，避免等待草稿错误对话框。曾结束本脚本拥有的卡住进程树；未结束用户预览。
- 同会话元数据刷新不应取消正在进行的文件操作。拆开列表请求更新与授权 / 会话生命周期；真实下载响应经过测试响应门，在新工具文件已经出现后才释放，完成状态与原始字节仍必须匹配。
- 第二次完整回归在既有资料组的 `page.screenshot` 等待 10 秒后超时（日志显示字体已加载）；此前 13 组 / 154 项通过。`4f4eab7` 改为 Electron `capturePage`，预热并等两帧，核对 1280×800 PNG 后保存；原来的 8 项断言全部保留，专项复测通过。原始失败 `p2-artifacts-desktop-full-final-20261005.log` 与专项 `p2-artifacts-profiles-capture-green-20261005.log` 保留；未把截图超时当成已确认的产品功能缺陷。

## 边界

- 只登记当前四种明确文件输出，不从命令 stdout、模型文字或导入历史猜测路径；中断 / 未保存结果仍走既有未知结果处理。
- 每文件最多 16 MiB；每页最多 20 项，校验读取合计最多 32 MiB，约 5 秒在文件系统操作间协作检查。未核对项显示状态，下载仍重新检查授权与 SHA-256。系统阻塞调用与持续外部路径替换攻击没有硬中断保证。
- 打开仍受现有查看器能力限制：2 MiB UTF-8 编辑，以及 4 MiB 图片 / PDF / DOCX 文字预览；其他二进制格式可以下载，不保证直接预览。
- 记录是原文件的引用，未保留每个产物版本副本；已变化的旧版本不可下载。原上传资源的批量清理、未来多媒体 / MCP 产物、真实账号和跨平台尚未完成，CA-WORK-011 保持部分实现。
- 中立备份不迁移这些本机路径引用与授权。完整产品发布门禁继续关闭。
