# CAgent 发布与更新

本仓库是 OpenHanako / HanaAgent 0.450.0 的个人维护分支，保留上游历史、署名及 Apache-2.0 许可证。

## 2026-09-27 补充修复

- 会话快照：覆盖写入之前检查磁盘中的消息 ID，拒绝丢失已落盘消息的过期快照。内嵌媒体清理、超长消息处理和会话续接共用这一检查。
- 原子保存：先完成整份 JSONL 序列化，再写临时文件并替换；序列化异常或替换失败保留原文件。文件修复还核对读取时的原始字节，避免用过期结果覆盖更新。
- 插件斜杠命令：`engine`、`hub`、`sessionOps` 仍可直接访问，但不再随上下文的 JSON 序列化或对象展开传给子进程；命令失败记录原始堆栈。
- Windows 打包：限制依赖追踪的跨盘绝对路径，避免追踪器误把用户目录当成运行资源而卡住。

这些修改覆盖了可复现的历史覆盖、写入截断及 Timeout 循环引用路径。原始 issue 的现场附件不足以证明原事故唯一由这些路径触发；已经丢失且没有备份的数据无法据此恢复。

回归包含 1,058 条历史记录、仅剩三条的内存快照、两个同时持有同一会话的管理器、序列化失败、替换失败、分支保留，以及真实插件加载后调用 Node 子进程并返回结果。会话与命令定向覆盖率：行 91.91%、语句 90.62%、分支 85.55%、函数 97.91%。更新源和打包依赖相关定向集 165 项通过。

完整回归仍受本机 Windows 创建符号链接权限影响，7 项安全测试在创建夹具时失败，未跳过测试或降低安全断言。详细基线见 [原修复记录](github-issue-fixes.md)。

默认来源统一定义于 `shared/release-source.cjs`。Electron 使用 generic provider 读取 Gitee 上的清单，失败不会切回原作者仓库。旧版邀请通道文件没有本仓库的 `repository` 标记时不会自动生效，原文件保留。原作者的邀请服务不再默认启用。

`HANA_UPDATE_FEED_URL` 仍是显式运维覆盖。没有设置它时使用上表。上游项目介绍、贡献者和参考资料中的 GitHub 链接仍是署名/文档链接，不是更新来源。

## 构建要求

Node 24.19.0、锁文件依赖、Electron 42.3.0。源码验证不调用收费模型。

安装包内的内容归档必须使用 Ed25519 签名，并将匹配的公开 keyset 编入 main bundle；保留签名校验，不采用绕过校验的开发开关。私钥留在工作区外，不上传 Gitee。

本机缺少 MSVC，未修改的 Windows 沙盒助手及 MinGit 从上游 v0.450.0 的官方 HanaCore 归档提取；对应源码与该 tag 一致。官方归档 SHA-256：`8f4f4616ce3748cefdbedcf6874728c1a42310cc56c516b1062e29619724438f`。MinGit 2.55.0 的 Git、Shell、提交和本地克隆 smoke 已通过。

后续发布必须更新版本号并上传相应安装包与校验清单；仅推送源码不会让已经安装的客户端获得新程序。
